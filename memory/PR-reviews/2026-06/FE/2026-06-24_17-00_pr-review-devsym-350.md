## Findings

### Should-fix

**[S1] `src/components/wizard/WizardModalShell.tsx:29` — Scroll container has `pointer-events-none`, making scrollbar non-interactive**

- **What's wrong:** The outer div (`fixed inset-0 z-[10060] overflow-y-auto overscroll-contain`) has `pointer-events-none`. Mouse-wheel scroll over the modal card still works because wheel events bubble from the inner `pointer-events-auto` card up to the scrollable ancestor. However, the scrollbar thumb becomes completely non-interactive (users cannot drag it), and touch-initiated scrolling that starts outside the card area won't work. This is a regression from the original code, where the scroll container had implicit pointer events.
- **Why:** The `pointer-events-none` wrapper is intentional — it lets clicks on the empty space around the card fall through to the backdrop button portal (z-10050) below. But this technique sacrifices interactive scrollbar.
- **Suggested fix:** Add `pointer-events-auto` back to the scroll container and remove the backdrop portal click handler from there; keep only the standalone backdrop `<button>` portal for close-on-backdrop clicks. Alternatively, add a thin transparent `pointer-events-auto` layer around the card (but not on the card) that calls `onClose`, while giving the scroll wrapper `pointer-events-auto`. This preserves both close-on-backdrop and scrollable overflow.

### Nits

**[N1] `src/features/task-create/CreateTaskFab.tsx:18` — Magic z-index values with no centralized reference**

- **What's wrong:** The PR introduces z-10050, z-10055, z-10060, z-10100, plus the existing z-9999, scattered across four files with no documented stacking context scale.
- **Why:** Future changes to any one value require updating all related values manually, with no single source of truth.
- **Suggested fix:** Add a comment block or a shared const (e.g., in `src/lib/z-index.ts`) documenting the stacking order: `backdrop=10050, fab-disabled=10055, modal=10060, toast=10100`. Not mandatory, but makes the intent auditable.

**[N2] `src/features/task-create/NewTaskButton.tsx` — Missing `aria-disabled` and `tabIndex` vs. `CreateTaskFab`**

- **What's wrong:** `CreateTaskFab` sets both `disabled`, `aria-disabled={blockingModalOpen}`, and `tabIndex={blockingModalOpen ? -1 : undefined}`. `NewTaskButton` only sets `disabled`. Native `disabled` already removes the button from the tab order and communicates the state to assistive technology, so the extra attributes on `CreateTaskFab` are actually redundant — but the inconsistency between the two components is worth noting.
- **Why:** Minor accessibility consistency concern; not a real bug.
- **Suggested fix:** Either add the extra attributes to `NewTaskButton` to match `CreateTaskFab`, or remove the redundant `aria-disabled` and `tabIndex` from `CreateTaskFab`. Either direction is fine.
